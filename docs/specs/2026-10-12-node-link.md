# feat(node)—`okfctl node link`: add a cross-reference without hand-editing

**Status:** Implemented · **Owner:** Casey West · **License:** Apache-2.0
**Source of truth:** OKF `SPEC.md` **v0.2** (upstream
`GoogleCloudPlatform/knowledge-catalog`, header confirmed `**Version 0.2**`)—§3
(a bundle is a directory tree), §3.1 (reserved filenames `index.md`, `log.md`),
§4.2 (the body is Markdown), §6.1 (links between concepts: `/`-absolute or
relative; consumers tolerate broken links), §8 (index files), §9 (log files),
§11 (conformance), §12 (versioning). No new spec behavior—this is an authoring
convenience; it adds no `validate` rule.
**Base:** `fix/write-safety-audit` @ `4f95f08`  **Branch:** `feat/node-link`

## Problem

`lint --semantic` reports `similar-unlinked`—two nodes that read alike with no
link between them—and stops there. Resolving it means opening a file, finding
or inventing a "Related" list, computing a relative path by hand, and copying a
title. Every step is a place to get the path wrong (a broken link §6.1 tolerates
but `lint` flags), to edit inside the frontmatter, or to add the same link twice.

## Design

```
okfctl node link <from> <to> [--section <heading>] [--dry-run] [--bundle <dir>]
```

`<from>` and `<to>` are bundle-relative node paths (`.md` optional, like the
sibling `node` commands). The command adds ONE Markdown link from `<from>`'s
body to `<to>`.

### Refusals (nothing is written)

| Case | Why |
|---|---|
| Either path escapes the root (`..`, OS-absolute, symlink out) or carries a control character | §3—the bundle *is* its directory tree. Resolved with `fsutil.ResolveInRoot`; errors wrap `fsutil.ErrEscapesRoot` / `fsutil.ErrInvalidPath`. |
| Either path is `index.md` or `log.md` at any level | §3.1, §8, §9—reserved files are not concept documents; okfctl maintains them. |
| `<from>` == `<to>` | A self-link is not a cross-reference. |
| `<from>` or `<to>` is not a loaded node | The target MUST exist: `node link` never writes a link that is broken on arrival. |
| A path contains whitespace, `(`, `)`, `<`, `>` | The shared link resolver cannot read such a destination back, so idempotency could not be proven. Reported as a limitation, not a spec rule. |
| `--section` is empty or carries a control character / `#` prefix | The heading text is written verbatim into the body. |

### What gets written

- **Link form—relative.** The destination is the path from `<from>`'s
  directory to `<to>`, slash-separated (`../payments/refunds.md`). §6.1 permits
  both forms and *recommends* the `/`-absolute one; okfctl writes relative
  because the roadmap specifies it and the corpus it is built against is 100%
  relative (zero `/`-absolute links across three bundles), so a relative link
  matches its neighbours. **This is a recorded tension with §6.1's
  recommendation**, surfaced for review rather than resolved silently; the
  reader (§6.1) accepts either, and the idempotency check below accepts either.
  One exception keeps the written link unambiguous: the shared resolver tries a
  relative destination root-relative before dir-relative, so if the relative
  spelling would ALSO name a different existing node from the bundle root, the
  `/`-absolute form (`/payments/refunds.md`) is written instead—the form §6.1
  recommends, and the only one that cannot be misread.
- **Link text** is `<to>`'s `title` (falling back to its file stem), with `\`
  backslash-escaped, `[` and `]` replaced by `(` and `)`, and control characters
  replaced by a space, so the text cannot close the link early or break the
  line. Brackets are replaced rather than escaped because the shared link
  scanner does not honour `\]`—an escaped bracket would hide the new link from
  the graph, from `lint`, and from this command's own idempotency check.
- **Placement—an authoring convention, not a spec rule.** OKF says nothing about
  where a cross-reference lives in the body (§4.2 is just "Markdown"). By
  default the link is a `* ` bullet (the corpus's bullet marker) appended to the
  end of the `## Related` section, which is created at the end of the body if
  absent. `--section <heading>` picks another `##` heading, created the same
  way. A heading match is exact text at level 2; a `## Related` line inside a
  fenced code block is code, not a heading, and is ignored.
- **Frontmatter is preserved byte-for-byte.** The file is split with the
  byte-preserving frontmatter splitter; only the body after the closing `---`
  is edited. `modified` is deliberately NOT bumped—that would rewrite the
  frontmatter, and `node refresh` exists for that. The file's line-ending style
  (LF or CRLF) is kept.
- **Writes** go only through `fsutil.WriteFileAtomic`. The file is re-read
  just before the write and the command refuses if it changed since it was
  planned, so a concurrent edit is never clobbered. On success a §9 log
  entry `linked <from> -> <to>` is appended via `okf.AppendLog`. `index.md` is
  not regenerated (§8 entries do not depend on body links).

### Idempotency

Before writing, every existing link in `<from>`'s body is resolved with the
SAME resolver that builds graph edges and that `lint`'s `similar-unlinked`
check uses (`scanNodeLinks`), plus a `#fragment`-stripped pass. Any spelling
that lands on `<to>`—relative, `./`-prefixed, root-relative, `/`-absolute,
with or without a `#fragment` or a CommonMark title—counts as "already
linked". The command then reports a no-op: no write, no log line, exit 0.
A link inside a code fence counts too, because the shared resolver (and so
`lint`) counts it; diverging here would make `node link` add a link that
`lint` already considers present.

### `--dry-run`

Prints the planned change (target file, section, created-or-existing, the bullet
line) and writes nothing: no node write, no log line.

### `similar-unlinked` hint

The `similar-unlinked` finding message gains the exact command that resolves
it: `resolve with: okfctl node link <a> <z>` (paths POSIX single-quoted when
they contain anything beyond letters, digits, and `/._-+:@%,=`). The finding's check name, path, score, and sort order are
unchanged. Only the hint text moves.

## Controls

- **Positive:** a link is added exactly once and one log line appears;
  traversal, self-links, and reserved files are refused.
- **Negative:** a second run is a byte-identical no-op with no log line; a
  differently-spelled existing link is detected; `--dry-run` touches nothing;
  a fenced `## Related` is ignored; a v0.1 node's frontmatter and `# Citations`
  survive untouched.

## Non-goals

- No `validate` or `lint` rule changes; the link form and placement are not
  enforced anywhere.
- No bidirectional linking, no bulk linking, no unlink.
- No rewrite of existing links into a canonical form.
